## Q1. Transformer为何使用多头注意力机制？（为什么不使用一个头）

**标准答案：**

Multi-Head Attention 将 Q/K/V 分别投影到 h 个低维子空间，在每个子空间独立计算注意力后拼接，再做线性变换。相比单头注意力，多头机制有三个优势：

1. **子空间多样性**：不同 head 可以在不同的表示子空间中捕捉不同类型的依赖关系（如句法关系、语义关系、位置关系）。论文附录的可视化证实了不同 head 确实学到了不同的 attention pattern。
2. **避免平均化效应**：单头注意力只能输出一组权重分布，相当于对所有类型的关系做平均，使得每种关系都捕捉得不够精确。
3. **计算成本不变**：由于每个 head 的维度从 d_model 降到 d_model/h（512→64），h 个 head 的总计算量与单头 d_model 维的 attention 基本相同。

Table 3 (A) 的消融实验验证了这一点：保持总计算量恒定，单头（h=1, d_k=512）比 8 头（h=8, d_k=64）差 0.9 BLEU；但头太多（h=32, d_k=16）效果也下降，因为每个头的维度太小，注意力质量退化。

**大白话：**

一次 Attention 只能学一种"看法"。但语言里一个词跟其他词的关系是多种多样的——"学习"跟"小明"是"谁在学"的关系，跟"数学"是"学什么"的关系。一个头只能把这些关系揉成一个平均数，什么都看到了但什么都看不清。多头就像派8个侦探各自独立调查，最后把8份报告合在一起，比1个侦探啥都管要靠谱得多。而且总工作量差不多，因为每个侦探只负责一小块。

## Q2. Transformer为什么Q和K使用不同的权重矩阵生成，为何不能使用同一个值进行自身的点乘？

**标准答案：**

如果 Q 和 K 使用同一个权重矩阵 W，即 Q=K=XW，那么注意力分数矩阵 A = QKᵀ = XWWᵀXᵀ。此时 A 是一个对称矩阵（A = Aᵀ），意味着 token i 对 token j 的注意力权重必然等于 token j 对 token i 的注意力权重。

这带来两个问题：

1. **注意力关系被强制对称**：现实中语义关系往往是非对称的。"动词关注宾语"和"宾语关注动词"的程度应该不同。对称约束严重限制了模型的表达能力。
2. **自注意力退化**：当 Q=K 时，每个 token 与自身的点积 qᵢ·kᵢ = ‖xᵢW‖² 往往是最大的（自身与自身最相似），导致 softmax 后自身权重占主导，模型倾向于"只看自己"，失去了注意力机制"看别人"的核心能力。

使用不同的 W_Q 和 W_K，注意力矩阵 A = XW_Q · W_Kᵀ · Xᵀ 不再对称，模型可以学到非对称的注意力关系，表达能力大大增强。

**大白话：**

Q 是"我在找什么"，K 是"我能提供什么"。这两件事本来就不一样——你找东西的标准和别人展示自己的方式应该是不同的角度。如果用同一个矩阵，就等于逼着"找什么"和"提供什么"变成同一个东西，那每个词跟自己最像（自己当然最了解自己想找什么），attention 就退化成"每个词只看自己"了，没有意义。分开用不同的矩阵，才能让"我找主语"和"他提供主语信息"这两个动作解耦。

## Q3. Transformer计算attention的时候为何选择点乘而不是加法？两者计算复杂度和效果上有什么区别？

**标准答案：**

论文提到两种主流 attention 计算方式：

- **Dot-Product（点乘）**：score(Q, K) = QKᵀ / √d_k
- **Additive（加法，Bahdanau 注意力）**：score(Q, K) = vᵀ · tanh(W₁Q + W₂K)

两者对比：

| 维度 | 点乘 Attention | 加法 Attention |
|------|---------------|---------------|
| 理论复杂度 | O(d) | O(d)（相同） |
| 实际速度 | 更快（矩阵乘法高度优化） | 更慢（需要 tanh + 额外参数） |
| d_k 较小时 | 效果相当 | 效果相当 |
| d_k 较大时 | 需要 scaling（除以√d_k），否则效果变差 | 不受影响 |

论文选择点乘的核心原因是**实际计算效率**：点乘可以直接用高度优化的矩阵乘法库（cuBLAS）实现，比加法注意力快很多且内存效率更高。理论复杂度一样，但工程实现上点乘有巨大优势。

加法注意力在 d_k 大时不需要 scaling 是因为 tanh 自带"压缩"效果，天然限制了输出范围。

**大白话：**

两种方法效果差不多，但点乘在 GPU 上算起来快得多。GPU 最擅长的就是矩阵乘法，点乘正好是矩阵乘法。加法注意力需要额外的参数、额外的 tanh 运算，工程上吃亏。论文的态度很实际：效果一样的情况下，谁快用谁。唯一的代价是维度大的时候点乘的值会变得很大，所以需要除以 √d_k 来缩放一下，这个代价很小。

## Q4. 为什么在进行softmax之前需要对attention进行scaled（为什么除以dk的平方根），并使用公式推导进行讲解

**标准答案：**

假设 Q 和 K 的每个分量都是独立的、均值为 0、方差为 1 的随机变量。

点积 q·k = Σᵢ qᵢkᵢ，其中每一项 qᵢkᵢ 的均值为 0、方差为 1（两个独立零均值单位方差变量之积的方差为 1）。

d_k 个这样的项求和后：
- 均值：E[q·k] = 0
- 方差：Var[q·k] = d_k

所以点积的标准差为 √d_k。当 d_k=64 时，标准差为 8，点积值可能在 [-24, 24] 的范围波动。

这些大数值进入 softmax 后会导致：
- softmax 输出趋近 one-hot 分布（一个接近 1，其他接近 0）
- softmax 在极端值处梯度几乎为 0（饱和区）
- 梯度消失，参数无法有效更新

除以 √d_k 后：
- Var[q·k / √d_k] = d_k / d_k = 1
- 点积被拉回到标准正态分布的范围
- softmax 输出是一个"有区分度但不极端"的分布
- 梯度正常流动，训练稳定

**大白话：**

点积就是把两个向量对应位置相乘再加起来。维度越高，加的项越多，总和自然越大——64 维就加了 64 项，结果可能是个很大或很小的数。

这些大数丢进 softmax 会怎样？softmax 看到 `[20, 1, -10]` 就会输出 `[0.9999..., 0.0000..., 0.0000...]`，几乎变成"非黑即白"，只关注一个词完全忽略其他。这不是我们想要的——注意力应该有区分度但不能极端。而且这种极端分布的梯度几乎为零，模型学不动。

除以 √d_k 就是把这些大数等比例缩小，拉回到合理范围，让 softmax 输出一个"有重点但不极端"的分布。

## Q5. 在计算attention score的时候如何对padding做mask操作？

**标准答案：**

Padding mask 用于处理变长序列。在一个 batch 中，不同句子长度不同，短句需要用 padding token（通常是 0）填充到统一长度。但 padding 位置不携带任何语义信息，不应参与 attention 计算。

具体操作：

1. 构造一个 mask 矩阵，shape 与 attention score 矩阵相同（n×n）
2. padding 位置对应的列（作为 Key 时）设为 True（需要 mask 的位置）
3. 在 softmax 之前，将 mask=True 的位置的 score 替换为一个极大的负数（如 -1e9 或 -inf）
4. softmax 后，这些位置的权重变为 ≈0，不对输出产生贡献

```python
# 伪代码
scores = Q @ K.T / sqrt(d_k)       # (batch, n, n)
scores = scores.masked_fill(padding_mask == 0, -1e9)
weights = softmax(scores, dim=-1)   # padding 位置权重 ≈ 0
output = weights @ V
```

注意：Padding mask 在 Encoder 和 Decoder 的所有 attention 层都需要使用（包括 cross-attention），而 causal mask（序列 mask）只在 Decoder 的 self-attention 中使用。两者可以同时存在，取并集即可。

**大白话：**

一个 batch 里句子长短不一，短句要用废话（padding）补到一样长。但这些废话不应该被任何词"关注"。做法很暴力：在算 attention 分数的时候，把所有废话位置的分数改成负无穷。负无穷过 softmax 就变成 0。效果就是：模型完全看不见 padding，就像它们不存在一样。

## Q6. 为什么在进行多头注意力的时候需要对每个head进行降维？

**标准答案：**

论文中 d_model=512，h=8，每个 head 的维度 d_k = d_v = d_model/h = 64。

必须降维的原因：

1. **计算成本控制**：如果每个 head 都用完整的 d_model=512 维，8 个 head 的总计算量是单头的 8 倍，参数量也是 8 倍，不可接受。降维到 64 维后，8 个 head 的总计算量 = 8 × O(n²×64) ≈ O(n²×512)，与单头 512 维的计算量相当。
2. **论文的设计哲学**：论文明确说 "due to the reduced dimension of each head, the total computational cost is similar to that of single-head attention with full dimensionality"。多头的收益来自子空间多样性，而不是增加计算量。
3. **实验验证**：Table 3 表明在总维度固定时，适当增加 head 数（减小 d_k）可以提升效果，但 d_k 太小（如 16）会导致注意力质量下降——每个 head 能"看到"的信息太少了。

**大白话：**

如果 8 个头每个都用 512 维，那计算量就是原来的 8 倍，太贵了。降维是为了"不多花钱"——把 512 维平均分成 8 份，每个头分 64 维。总工作量跟用一个 512 维的头差不多，但效果更好，因为 8 个头各管各的，比 1 个头什么都管更有效。这就是"不加价但升级服务"。

## Q7. 大概讲一下Transformer的Encoder模块？

**标准答案：**

Encoder 由 N=6 个相同的层堆叠而成。每个 Encoder 层包含两个子层：

**子层 1：Multi-Head Self-Attention**
- 输入序列中每个位置对所有位置计算注意力
- Q、K、V 都来自同一个输入（这是"self"的含义）
- 8 个 head 并行计算，拼接后线性变换
- 输出 shape 与输入相同：(batch, n, d_model)

**子层 2：Position-Wise Feed-Forward Network**
- 两层全连接：d_model(512) → d_ff(2048) → d_model(512)
- 中间用 ReLU 激活
- 每个位置独立做同样的变换

**每个子层都有：**
- **残差连接（Residual Connection）**：output = SubLayer(x) + x
- **层归一化（Layer Normalization）**：对残差连接的结果做 LayerNorm

完整的一个 Encoder 层的数据流：

```
x → Multi-Head Attention → Dropout → Add(+x) → LayerNorm → 
  → FFN → Dropout → Add(+上一步输出) → LayerNorm → 输出
```

此外，在进入第一个 Encoder 层之前，输入经过：
1. Token Embedding（词→向量，乘以 √d_model）
2. 加上 Positional Encoding（sin/cos 位置编码）
3. Dropout

**大白话：**

Encoder 就是把一句话"读懂"的过程，分 6 轮进行。每一轮做两件事：第一件是"互相看"——每个词看看其他词跟自己什么关系（Attention）；第二件是"自己想"——每个词拿着收集到的信息自己做一次深加工（FFN）。每做完一件事都有一个"保底机制"（残差连接），防止加工过程中把原始信息丢了。6 轮下来，每个词都充分理解了自己在整句话中的角色和含义。

## Q8. 为何在获取输入词向量之后需要对矩阵乘以embedding size的开方？意义是什么？

**标准答案：**

Embedding 矩阵通常以均值 0、方差约 1/d_model 进行初始化（如 Xavier/Glorot 初始化）。此时每个 embedding 向量各分量的方差为 1/d_model，整个向量的 L2 范数约为：

‖embedding‖ ≈ √(d_model × 1/d_model) = 1

而 Positional Encoding 使用 sin/cos 函数，每个分量值域为 [-1, 1]，L2 范数约为 √(d_model/2)。当 d_model=512 时：

- Embedding 范数 ≈ 1
- Positional Encoding 范数 ≈ 16

两者直接相加，位置信息的量级是语义信息的 16 倍，语义信息被完全淹没。

乘以 √d_model（≈22.6）后，embedding 范数也提升到 √d_model 量级，与 positional encoding 处于同一尺度，两者相加时语义和位置信息都能被有效保留。

此外，论文中 embedding 权重矩阵与 decoder 输出端 softmax 前的线性变换共享（weight tying），乘以 √d_model 的缩放可以确保共享权重在两个用途下数值尺度都合理。

**大白话：**

Embedding 初始化出来的值很小（范数大约是 1），而 Positional Encoding 用的 sin/cos 值在 -1 到 1 之间，范数有十几。两个直接加在一起，就像一个说话声音只有 1 分贝的人和一个声音 16 分贝的人一起说话——你只听得见声音大的那个。乘以 √d 就是给说话声音小的那个人一个扩音器，让两个人音量差不多大，都能被听见。

## Q9. 简单介绍一下Transformer的位置编码？有什么意义和优缺点？

**标准答案：**

**什么是位置编码：**

Transformer 没有循环结构，无法像 RNN 一样天然感知序列顺序。位置编码（Positional Encoding）为每个位置生成一个 d_model 维的向量，与 embedding 相加，使模型感知 token 的位置信息。

**论文使用的方案——正弦/余弦位置编码：**

$$PE_{(pos, 2i)} = \sin(pos / 10000^{2i/d_{model}})$$
$$PE_{(pos, 2i+1)} = \cos(pos / 10000^{2i/d_{model}})$$

其中 pos 是位置索引，i 是维度索引。每个维度使用不同频率的 sin/cos 函数。

**意义：**
- 让模型知道"谁在前谁在后"
- sin/cos 函数的线性变换性质使得模型可以通过简单的线性运算学到相对位置信息：PE(pos+k) 可以表示为 PE(pos) 的线性变换

**优点：**
- 不需要额外参数（不增加模型大小）
- 理论上可以外推到训练时未见过的序列长度
- 确定性的，不需要学习

**缺点：**
- 绝对位置编码，对相对位置的建模是间接的（依赖模型自己学会从绝对位置推断相对位置）
- 实际外推能力有限——虽然理论上 sin/cos 可以推广到任意长度，但实践中模型在远超训练长度的位置上表现会退化
- Table 3 (E) 表明可学习的 positional embedding 效果几乎一样，说明 sin/cos 的理论优势在实际中并不突出

**大白话：**

Attention 本身不知道词的顺序——"我爱你"和"你爱我"在它看来一模一样。位置编码就是给每个位置打一个"座位号标签"，贴在词向量上。论文用 sin/cos 波来做这个标签，好处是不需要训练、理论上能适应任意长度。坏处是它用的是绝对位置（"我在第3个位置"），而不是相对位置（"我在你前面两个位置"），后来的 RoPE 就是为了解决这个问题。

## Q10. 你还了解哪些关于位置编码的技术，各自的优缺点是什么？

**标准答案：**

| 方法 | 类型 | 优点 | 缺点 |
|------|------|------|------|
| **Sinusoidal PE**（原始 Transformer） | 绝对、固定 | 无参数、理论外推 | 相对位置间接建模，实际外推有限 |
| **Learned PE**（BERT、GPT-1） | 绝对、可学习 | 适应性强、效果好 | 无法外推超过训练长度、额外参数 |
| **Relative PE**（Transformer-XL, Shaw et al.） | 相对、可学习 | 直接建模相对位置、外推能力更好 | 实现复杂、计算开销大 |
| **RoPE**（Su et al., 2021, LLaMA/GPT-NeoX） | 相对、固定 | 相对位置直接编码在注意力中、旋转矩阵数学性质优美、外推能力强 | 实现需改 attention 内部、高频信息可能衰减 |
| **ALiBi**（Press et al., 2022, BLOOM） | 相对、无参数 | 极简（直接在 attention score 上加线性偏置）、外推能力极强 | 对短距离关系建模可能不如 RoPE 精细 |

当前主流趋势：RoPE 是最广泛使用的方案（LLaMA、Qwen、Mistral 等都在用），ALiBi 在某些场景下因为简单高效也有使用。原始的 sinusoidal 和 learned PE 已较少在新模型中出现。

**大白话：**

原始 Transformer 用 sin/cos 绝对位置——就是给每个座位贴个固定编号。后来 BERT 改成可学习的编号——让模型自己决定每个位置应该长什么样。再后来大家发现，比起"我在第3个位置"，更有用的信息是"我在你前面2个位置"，于是发展出了相对位置编码。RoPE 是目前最流行的方案，它通过旋转向量的角度来编码位置，数学性质特别好，现在几乎所有主流大模型都在用。

## Q11. 简单讲一下Transformer中的残差结构以及意义。

**标准答案：**

残差连接（Residual Connection）源自 ResNet（He et al., 2016），在 Transformer 中的形式为：

$$\text{output} = \text{LayerNorm}(x + \text{SubLayer}(x))$$

每个子层（Multi-Head Attention 和 FFN）的输出都与其输入相加后再做 LayerNorm。

**三个核心意义：**

1. **缓解梯度消失**：深层网络中梯度需要经过多层反向传播，容易逐层衰减到接近零。残差连接提供了一条"高速公路"，梯度可以直接从输出端传回输入端（加法操作的梯度是 1），保证深层也能有效更新。

2. **保留原始信息**：如果子层的变换不好（早期训练时常见），残差连接保证输出至少不会比输入差——最坏情况下 SubLayer(x)≈0，输出就等于输入本身。这降低了"加一层反而变差"的风险。

3. **降低优化难度**：子层只需要学习"输入和输出的差（残差）"，而不需要从零学习整个映射。学习差值通常比学习完整映射容易得多。

**在 Transformer 中的额外意义：** Transformer 有 6 层 encoder × 2 个子层 = 12 次变换。没有残差连接，12 层深的网络几乎不可能训练。

**大白话：**

残差连接就是"做完变换之后，把原始输入加回去"。这有三个好处：一是防止深层网络梯度消失（给梯度开了一条直通隧道，不用层层传递）；二是保底（就算这一层学废了，加回原始输入至少不会变得更差）；三是降低学习难度（只需要学"跟原始输入的差距"，而不是从头学起）。简单来说就是一个安全网——有它模型可以放心地堆很多层。

## Q12. 为什么transformer块使用LayerNorm而不是BatchNorm？LayerNorm在Transformer的位置是哪里？

**标准答案：**

**为什么用 LayerNorm 而不是 BatchNorm：**

1. **序列长度不一致**：NLP 中不同样本的序列长度不同。BatchNorm 在 batch 维度上统计均值和方差，要求同一特征位置在 batch 内可比较。但对于变长序列，不同样本的第 k 个位置可能对应完全不同的词，跨样本统计没有意义。

2. **Batch 维度依赖**：BatchNorm 需要足够大的 batch size 来稳定统计量。在推理时需要使用训练时的 running mean/variance，引入训练-推理不一致。LayerNorm 在单个样本的特征维度上归一化，与 batch size 无关，训练和推理行为一致。

3. **序列任务特性**：NLP 中同一个位置在不同句子中的语义完全不同（第3个词可能是名词也可能是动词），对 batch 中的同一位置求统计量是不合理的。LayerNorm 对单个 token 的 d_model 维特征做归一化，保证每个 token 的表示在合理范围内。

**LayerNorm 的位置：**

原论文（Post-LN）：放在残差连接之后。

$$\text{output} = \text{LayerNorm}(x + \text{SubLayer}(x))$$

现代实现（Pre-LN，如 GPT-2 之后）：放在子层之前。

$$\text{output} = x + \text{SubLayer}(\text{LayerNorm}(x))$$

Pre-LN 训练更稳定（梯度分布更均匀），不需要精心的 warmup 策略，现已成为主流。

**大白话：**

BatchNorm 是"看看班上其他同学这道题的平均水平来评估你"。但 NLP 里一个 batch 的句子长短不一、内容不同，第3个位置可能是"猫"也可能是"跑"，拿这些八竿子打不着的东西算平均没有意义。LayerNorm 是"只看你自己这个词的所有维度，把它们拉到标准范围"——不跟别人比，只管自己。而且 LayerNorm 不依赖 batch size，推理的时候行为和训练一样，更省心。

## Q13. 简答讲一下BatchNorm技术，以及它的优缺点。

**标准答案：**

**原理：** BatchNorm（Ioffe & Szegedy, 2015）对 mini-batch 内同一特征维度的值做归一化，使其均值为 0、方差为 1，然后通过可学习的 γ（缩放）和 β（偏移）参数恢复表达能力。

$$\hat{x}_i = \frac{x_i - \mu_B}{\sqrt{\sigma_B^2 + \epsilon}} \quad \rightarrow \quad y_i = \gamma \hat{x}_i + \beta$$

**优点：**
- 加速训练收敛（内部协变量偏移减少，允许使用更大的学习率）
- 有轻微的正则化效果（每个 batch 的统计量有随机性）
- 在 CNN / CV 领域效果显著，几乎是标配

**缺点：**
- 依赖 batch size：batch 太小时统计量不稳定，效果退化
- 训练-推理不一致：训练用 batch 统计量，推理用 running mean/variance
- 不适合变长序列：NLP 中序列长度不同，同一位置跨 batch 统计没有意义
- 不适合 RNN / Transformer 等序列模型

**大白话：**

BatchNorm 就是"看一个班同学同一道题的分数，把大家拉到平均线附近"。好处是训练更快更稳定，在图像处理领域几乎人人都用。坏处是需要"同学够多"（batch size 不能太小），而且考试（推理）的时候用的是平时（训练时）记录的班级平均，可能不完全准确。最大的问题是在 NLP 里不好用——因为每个"同学"的卷子（句子）长度不同，同一道"题"（同一个位置）对不同同学来说根本不是同一回事。

## Q14. 简单描述一下Transformer中的前馈神经网络？使用了什么激活函数？相关优缺点？

**标准答案：**

**结构：** 两层全连接网络，对每个位置独立且相同地应用。

$$\text{FFN}(x) = \max(0, xW_1 + b_1)W_2 + b_2$$

- 第一层：d_model(512) → d_ff(2048)，"扩展"
- 激活函数：ReLU = max(0, x)
- 第二层：d_ff(2048) → d_model(512)，"压缩"

**为什么用 ReLU：**
- 计算简单高效（只是一个 max 操作）
- 缓解梯度消失（正区间梯度恒为 1）
- 引入非线性（没有激活函数，多层线性变换等价于一层）

**ReLU 的缺点：**
- "神经元死亡"（Dead ReLU）：如果某个神经元的输入始终为负，梯度永远为 0，该神经元永久失活
- 输出非零中心化：所有输出 ≥ 0，可能影响后续层的优化

**后续改进：**
- BERT 使用 GELU（高斯误差线性单元），更平滑的近似 ReLU
- LLaMA 使用 SwiGLU（Swish + Gated Linear Unit），效果更好但参数稍多
- 现代大模型普遍采用 GELU 或 SwiGLU 替代 ReLU

**为什么中间维度是 4 倍：**
- 先升维再降维的"瓶颈"结构让模型在更高维的空间做非线性变换，提取更丰富的特征
- 4 倍是经验值，后续工作验证了 3-4 倍是较优的比例

**大白话：**

FFN 就是每个词"自己想一想"的过程。先把 512 维的信息"展开"成 2048 维（给自己更大的思考空间），用 ReLU 过滤一下（负数清零——扔掉不要的信息），再"压缩"回 512 维。ReLU 简单粗暴但有效，后来的模型换成了更精细的激活函数（GELU、SwiGLU），但核心思路没变：先展开、激活、再压缩。

## Q15. Encoder端和Decoder端是如何进行交互的？

**标准答案：**

Encoder 和 Decoder 通过 **Cross-Attention（交叉注意力）** 进行交互，它是 Decoder 每一层中的第二个子层。

**具体机制：**
- **K 和 V 来自 Encoder 最后一层的输出**
- **Q 来自 Decoder 当前层的自注意力输出**

```
Decoder 自注意力输出 → 作为 Q
Encoder 最终输出 → 作为 K 和 V
Q × Kᵀ → attention weights（Decoder 的每个位置对 Encoder 每个位置的关注度）
weights × V → 从 Encoder 中提取的上下文信息
```

**直觉理解：**
- Decoder 生成每个词的时候，用当前已有的信息（Q）去 Encoder 的输出里"查找"最相关的源语言信息（K/V）
- 这本质上是 seq2seq 中 Bahdanau Attention 的推广：原本是 RNN decoder 的隐状态作为 Q，对 encoder 所有隐状态做 attention。Transformer 把它升级为多头版本

**与 Self-Attention 的区别：**
- Self-Attention：Q、K、V 全来自同一个序列
- Cross-Attention：Q 来自 Decoder，K/V 来自 Encoder——这是"cross"（交叉）的含义

**大白话：**

就像翻译时，你已经写了半句中文（Decoder 的状态），现在要决定下一个中文词写什么。你回头看英文原文（Encoder 的输出），用你当前的语境（Q）去英文原文里找最相关的信息（K/V）。Cross-Attention 就是 Decoder 向 Encoder "提问"的机制——"我现在写到这里了，原文里哪部分跟我现在要写的最相关？"

## Q16. Decoder阶段的多头自注意力和Encoder的多头自注意力有什么区别？（为什么需要decoder自注意力需要进行sequence mask）

**标准答案：**

Encoder 和 Decoder 的 Self-Attention 在结构上完全相同，唯一的区别是 Decoder 多了一个 **Causal Mask（因果 mask / sequence mask）**。

**为什么需要 Causal Mask：**

Transformer 的训练使用 **Teacher Forcing**：把完整的目标序列作为 Decoder 输入，一次性并行计算所有位置的输出。如果不加 mask，位置 t 可以看到位置 t+1、t+2 … 的信息——这等于"提前看到正确答案"，模型不需要学习预测，只需要复制未来的 token。

Causal Mask 的操作：构造一个上三角矩阵，将对角线以上的位置（未来位置）设为 -inf，softmax 后这些位置权重为 0。这确保位置 t 只能看到位置 1, 2, …, t 的信息。

```
Mask 矩阵示意（√ = 可见, × = 被遮挡）：
     pos1  pos2  pos3  pos4
pos1   √     ×     ×     ×
pos2   √     √     ×     ×
pos3   √     √     √     ×
pos4   √     √     √     √
```

**为什么 Encoder 不需要：**

Encoder 处理的是完整的源序列（如英文原文），不存在"未来信息泄露"的问题。相反，Encoder 需要每个词都能看到所有其他词，才能充分理解整句话的含义。

**推理时的区别：**

推理时 Decoder 是自回归的（一个一个词生成），天然就看不到未来，所以 mask 只在训练时有意义。但训练时如果不加 mask，模型会学到"作弊的捷径"，推理时就会崩溃。

**大白话：**

训练的时候，Decoder 一次性能看到完整的目标句子（老师直接把答案放在卷子上了）。如果不挡住，每个位置都能直接抄后面的正确答案，模型就学不到任何东西。Causal Mask 就是"遮答案的纸"——做第3题的时候，只能看到第1、2、3题，第4题以后全挡住。Encoder 不需要挡是因为原文是现成的，不存在"偷看未来"的问题。

## Q17. Transformer的并行化体现在哪个地方？Decoder端可以做并行化吗？

**标准答案：**

**Encoder 的并行化（完全并行）：**

1. **Self-Attention 层**：注意力分数矩阵 QKᵀ 是一次矩阵乘法，所有 token 对的分数同时算出。不存在串行依赖。
2. **FFN 层**：每个位置独立做同样的变换（position-wise），所有位置可以并行。
3. **Multi-Head**：所有 head 独立计算，可以并行。
4. **层间**：只有层间是串行的（第2层必须等第1层算完），但层内完全并行。

对比 RNN：RNN 的 h_t 依赖 h_{t-1}，n 个 token 必须串行 n 步。Encoder 的 Self-Attention 是 O(1) 步。

**Decoder 的并行化：**

- **训练时：可以并行。** 使用 Teacher Forcing + Causal Mask，Decoder 也可以一次性输入完整目标序列，用 mask 防止信息泄露，所有位置的输出并行计算。这是 Transformer 训练速度远超 RNN 的关键。
- **推理时：不能并行。** 自回归生成必须一个一个词生成，因为第 t+1 个词的输入依赖于第 t 个词的输出。这是 Decoder 的固有限制，也是后续 Speculative Decoding 等加速技术要解决的问题。

**大白话：**

Encoder 完全并行——所有词同时互相看、同时各自想，就像全班同学同时开卷考试。Decoder 训练的时候也能并行——虽然要挡住未来答案，但挡住之后全班还是能同时答题。推理的时候就不行了——因为你要先生成第1个词，才知道第2个词该写什么，只能一个一个来，像一个人独自写作文。

## Q19. Transformer训练的时候学习率是如何设定的？Dropout是如何设定的，位置在哪里？Dropout在测试的需要有什么需要注意的吗？

**标准答案：**

**学习率（Warmup + Decay）：**

$$lr = d_{model}^{-0.5} \cdot \min(step^{-0.5}, \; step \cdot warmup\_steps^{-1.5})$$

- 前 warmup_steps=4000 步：学习率**线性增大**（从 0 逐步升到峰值）
- 4000 步之后：学习率按步数的**平方根倒数衰减**（逐渐减小）

这样做的原因：训练初期参数随机，梯度方向不稳定，大学习率会导致训练崩溃。先用小学习率让模型"找到方向"，再加大步伐快速学习，最后减速精调。

**Dropout 设置：**

Dropout rate = 0.1，应用在以下位置：
1. 每个子层（Attention、FFN）的输出，在加残差连接之前
2. Attention 权重矩阵上（对 softmax 后的 attention weights 做 dropout）
3. Embedding + Positional Encoding 相加之后

**测试时的注意事项：**

测试/推理时 Dropout **必须关闭**（PyTorch 中通过 `model.eval()` 实现）。如果不关闭：
- 输出具有随机性，同一个输入可能得到不同结果
- 有效参数被随机丢弃，模型性能下降
- 注意 PyTorch 中 `model.eval()` 会同时关闭 Dropout 和切换 BatchNorm 为推理模式

**大白话：**

学习率像开车——刚上路慢慢加速（warmup），到了高速正常跑（峰值），快到目的地慢慢刹车（decay）。Dropout 就是训练时随机让一些神经元"请假不干活"，逼剩下的神经元更努力、更独立，防止大家"抱团过拟合"。但考试（推理）的时候所有神经元必须全到场——把 Dropout 关掉，否则模型就是少了人在干活，效果会变差而且结果不稳定。

## Q20. 解码端的残差结构有没有把后续未被看见的mask信息添加进来，造成信息的泄露？

**标准答案：**

**不会泄露。** 残差连接不会引入任何未来信息。

分析数据流：

```
x_masked = MaskedSelfAttention(x)   ← 这里已经通过 causal mask 屏蔽了未来信息
output = LayerNorm(x + x_masked)    ← 残差连接加的是原始输入 x
```

关键在于理解"x"是什么：
- x 是当前层的输入，它已经是前一层的输出
- 在第一层，x 就是 embedding + positional encoding，每个位置只包含自身的信息
- 经过 Masked Self-Attention 后，x_masked 中每个位置只聚合了当前及之前位置的信息
- 残差连接把 x（自身位置信息）加上 x_masked（当前及之前位置的聚合信息），不涉及未来

逐层推导：
- 位置 t 的 embedding 只包含 token t 的信息（无泄露）
- Masked Attention 只允许 t 看 1…t（无泄露）
- 残差加的是位置 t 的输入（只有 t 自身或 1…t 的聚合信息）
- FFN 是 position-wise 的，不跨位置，不会引入其他位置信息
- Cross-Attention 的 K/V 来自 Encoder（源序列不存在泄露问题）

每一步都保证了位置 t 只能接触到位置 1…t 的信息，残差连接不会破坏这个约束。

**大白话：**

残差连接加回去的是"自己原来的输入"，而这个输入本身就不包含未来信息。打个比方：你做第3题的时候，Attention 只看了第1、2、3题（mask 保证的），然后残差连接加回的是"你做第3题之前的状态"——这个状态里也只有你自己第3题位置的信息，不包含第4、5题的答案。所以从头到尾，未来信息都进不来。
